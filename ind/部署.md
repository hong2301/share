# Indiegogo 评论采集 · 多实例部署说明

## 文件说明

本文件夹包含两份文件：

- `links.csv` — 链接数据（`sortId,link,status,comment_count,actual_count,备注`），约 11 万条
- `main_api.py` — 评论采集脚本（遍历 `links.csv` 中 `status=pending` 的链接，用 DrissionPage + requests 采集评论）

## 部署方式：复制多份，分文件夹跑

把这**两份文件**复制出 **5 份**，分别放进 5 个文件夹，一个文件夹独立跑一个采集实例。

每个文件夹负责约 **1 万条**链接（按 `sortId` 区间切分）。

### 1. 建 5 个文件夹

例如（按 1 万一个区间切分）：

| 文件夹 | 负责的 sortId 区间 |
| --- | --- |
| `ind-0` | 0 – 9999 |
| `ind-1` | 10000 – 19999 |
| `ind-2` | 20000 – 29999 |
| `ind-3` | 30000 – 39999 |
| `ind-4` | 40000 – 49999 |

> 如果链接总数超过 5 万，按此规律继续加文件夹即可（如 `ind-5`：50000 – 59999）。

### 2. 每个文件夹放一份文件

把 `links.csv` 和 `main_api.py` 复制到每个文件夹，然后把 `links.csv` 只保留自己负责的 `sortId` 区间（连同表头一起保留）。

### 3. 修改浏览器端口（必须唯一）

每份 `main_api.py` 里的 `BROWSER_PORT` 都要改成**唯一**的端口，不能与其他实例重复。

例如：

- `ind-0`：`BROWSER_PORT = 4830`
- `ind-1`：`BROWSER_PORT = 4831`
- `ind-2`：`BROWSER_PORT = 4832`
- `ind-3`：`BROWSER_PORT = 4833`
- `ind-4`：`BROWSER_PORT = 4834`

> 注意：`main_api.py` 头部注释里提到的示例端口（4824）只是示意，实际生效的是代码里的 `BROWSER_PORT` 变量。

### 4. 分别启动并运行

每个文件夹独立执行：

1. 用对应端口启动浏览器（DrissionPage 连接模式），并完成 Cloudflare 验证
2. 在该文件夹内运行：

```bash
python3 main_api.py
```

## 注意事项

- 每个实例的 `BROWSER_PORT` 必须全局唯一，端口冲突会导致连接错误
- 采集输出（`comments_out_api` 等目录）会生成在各实例自己的文件夹内，互不影响
- 多实例同时跑时注意网络/反爬压力，建议错峰或限速
- 每个文件夹内的 `links.csv` 只保留自己负责的区间，否则会重复采集
